Secure Web Architecture — Design Write-up

Application: Cybersecurity Research Workbench. Design objective: allow students to explore labs and save reports while protecting identities, report ownership and stored data.

The proposed architecture separates the frontend, web server, application layer and database. The HTML/CSS/JavaScript frontend communicates through HTTPS with an Nginx reverse proxy. The proxy serves static content and forwards API requests to a private Node.js application. Only the application may query the private PostgreSQL database. This separation limits public exposure and gives each layer a defined responsibility.

Authentication uses an OpenID Connect provider, with MFA for administrators. Authorization is a separate application decision: students access their own reports, instructors review assigned students, and administrators manage accounts. Every request must pass role and ownership checks, regardless of what the interface displays.

Encryption protects traffic with TLS and protects database volumes and backups with managed encryption keys. Opaque session cookies use Secure, HttpOnly and SameSite attributes; server-side records support expiry, rotation and immediate logout revocation. CSRF tokens and Origin checks protect state-changing requests.

Server-side input validation restricts request types, fields, sizes and formats. Parameterized queries keep data separate from SQL instructions, while safe DOM rendering and contextual output encoding prevent untrusted text from becoming executable markup. Redacted audit events support investigation without retaining passwords, API keys or session tokens.

Security is incorporated at each trust boundary rather than delegated to the frontend. The current single-file website demonstrates security concepts; the proposed private services and enforceable backend controls still need implementation. Verification would include cross-user access tests, revoked-session checks, injection payload tests and backup restoration.
